## Findings

Both snapshots' AGENTS.md context pointers condition profile discovery on already
using the named Harness skill. That is a circular trigger, while separate
architecture/testing prose can satisfy ordinary document-loading without ever
selecting the Harness. The installed public router description covers product
engineering and assurance but omits shared methodology and evidence-policy work;
internal specialist descriptions are explicit-only, so they cannot repair that
initial discovery gap by themselves. GitHub has no native invocation trace or
review comments for these PRs: the structural cause is evidenced, but the exact
agent selection history and causal contribution of each pointer are unavailable.

PR #9 has canonical performance documentation, a paired-campaign runner,
comparator and host-admission machinery. Its profile sources and exact-evidence
enforcement entry do not identify these performance owners. Existing discovery
excludes docs from capability scanning and only proposes a small set of sources.
Its declaration of 50.65s → 38.65s, 196 correctness checks per sample and zero
regressions across 526 compared metrics remains **reported single-pair evidence**;
we did not execute its private artifacts or certify product correctness. The
canonical comparator requires repeated qualification; a clean diagnostic pair
cannot replace that requirement. PR #9 already describes this distinction well.

## Bounded correction

The existing router now names methodology work and selects Verification and
Operations. One conditional reference owns the promotion sequence and points to
repository policy rather than copying performance numbers. Existing schema-2
sources and invariant enforcement entries register canonical policy, owner/rung
and artifacts; the profile helper audits those registrations read-only. The
package applies its own audit through the existing validator. No specialist,
invariant, schema or parallel execution framework is added.

The audit detects conventional source locations plus explicitly supplied paths.
It reports circular explicit-invocation pointers, missing registration, ownership
and missing/escaping references. Passing the audit means registration integrity,
not that an executable enforces the prose or that a recorded rung has been proven.
Local filenames and symbolic owners outside this bounded path audit may require
manual review. Product work remains separate; discovery of a gap authorizes a
proposal, not product-PR expansion or acceptance-rule changes.
