review found that Python decoding keeps the last duplicate JSON member. Raw result
evidence containing `"status":"fail","status":"pass"`, or terminal evidence
containing `"ok":false,"ok":true`, issues PASS and permits reuse. The same report
with an ordinary unambiguous failure is rejected. A scratch-file reproduction
confirmed both paths through `issue` and `reuse` while retaining valid reuse.

The applicable local DESIGN.md explicitly rejects duplicates and failures. This
finding is assessed under that evidence contract, not a universal requirement for
all JSON consumers. It is not counted as an unsupported baseline blocker. The
qualification suite did not cover conflicting duplicate members; its earlier
passes do not establish defect absence.

Baseline trial 1 and both candidate trials returned clean dispositions and missed
this material path. These are **initial-review misses on their evaluated
snapshots**. The defect was present before the campaign; it is neither a correction
introduced during the campaign nor a previously declared unavailable surface.

complete clean/defective calibration or a full behavioral pass. The candidate
