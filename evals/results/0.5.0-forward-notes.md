# 0.5.0 Development Forward Tests

Date: 2026-09-05. These are qualitative development observations from seven
fresh reviewer/implementer sessions using explicit router invocation and
synthetic fixtures. They are not a passing release receipt, a natural-prompt
selection benchmark, or an installed-versus-control comparison.

The entrypoint and instructions were edited between some trials. Per-trial
instruction snapshots, exact model identifiers, token/latency measurements,
and complete tool transcripts were not retained. Skill selections below are
reviewer-reported; exact loading order is unobservable in these notes. This
limits reproducibility and prevents treating these results as a frozen-policy
reliability claim. Earlier misses are retained alongside retests.

| Trial | Fixture | Observed behavior | Disposition |
| --- | --- | --- | --- |
| Privacy, initial | `erasure-telemetry` | Reproduced buffer → erase → flush recreating sensitive activity metadata, but selected no specialist because it treated review as outside Change/Harden. | Routing miss. Added explicit Change review mode. |
| Security | `handoff-session` | Selected security assurance. Demonstrated a provider-browser token authenticating product requests through query and cookie paths; reported missing audience/purpose checks and replay exposure. | Useful security finding; token-service internals and independent release review remain outside coverage. |
| Contention, initial | `critical-audit` | Demonstrated the current audit callback blocking revocation. Proposed audit after commit and proved that request's ordering, but did not establish progress against another audit writer holding the shared lock. Also selected verification because evaluation framing mentioned independent testing. | Incomplete design/proof. Strengthened the concurrent-writer and response-bound completion checks; separated evaluator metadata from user intent on retest. |
| Privacy, retest | `erasure-telemetry` | Selected privacy assurance plus data and interface specialists. Reproduced both pre-erasure buffered writes and new post-erasure activity recreating events. | Relevant reviewer reached; extra implementation-skill loading remained. Added an explicit assurance-only shortcut afterward; that final shortcut has no further privacy retest in this record. |
| Export implementation | `authorization-export` | In an isolated copy, bound the original account and export purpose, checked current authority around reads, and used the sink's atomic write fence. Five focused tests passed for success, account switch, consent withdrawal, permission loss, and sink denial. | Host-level implementation evidence only. Provider reads remain non-atomic with local revocation; already disclosed bytes cannot be recalled. Selected interfaces plus security/privacy assurance. |
| Contention, retest | `critical-audit` | Omitted the optional event from revocation and explicitly required isolation of other audit writers sharing locks/connections. Demonstrated that an already-held audit row lock still blocks a naive revoke. | Core design corrected. Selected architecture and security plus an additional privacy reviewer; real database timing/capacity remains unproven. |
| Uncatalogued threat | `uncatalogued-assurance` | Selected security assurance. Demonstrated relative traversal, absolute paths, and symlinks reading outside the member's root; reported material disclosure against the repository contract without requiring a path-traversal invariant. | Useful evidence that findings can extend beyond catalog vocabulary; limited to the fixture's download path. |

The export route expectation was narrowed after inspecting the fixture: it
changes authorization around an existing sink, without a new persisted or
derived representation. The interface owner plus security/privacy review is
sufficient; requiring a separate data implementation specialist would add
unjustified work. This expectation correction is not a retroactive claim that
the original expected route was observed.

The standalone local-documentation case and the full updated natural-prompt
matrix were not executed in these trials. The unchanged historical 0.4.0 receipt
does not provide that missing evidence. Next reliability evaluation must freeze
one policy snapshot, retain sanitized replayable outputs, repeat trials, and
test natural discovery with competing installed skills.
