# Route the unresolved experience decision

Use one primary owner for meaningful changes or explicit critique:

| Unresolved decision | Owner |
| --- | --- |
| User/job, task, IA/navigation, information priority, state/recovery | [Product Experience](../skills/product-experience/SKILL.md) |
| Hierarchy/composition, density, responsive presentation, accessible interaction | [Interface Design](../skills/interface-design/SKILL.md) |
| Proposed/accepted identity and visual intent, naming, voice, product wording/trust | [Brand and Language](../skills/brand-and-language/SKILL.md) |

Established intent with a typo, small spacing/alignment/icon correction, settled
accessible name, component reuse, or broken handler usually needs only focused
work. A fetch bug restoring accepted display need not activate design reasoning.
File location is not a trigger. Add another owner only for a separate unresolved
decision; reading a needed contract does not require its owner's full skill body.

Implementation still completes the existing builder scope checkpoint before any
primary skill or production edit. Material product/IA/identity expansion widens an
accepted contract and needs its explicit approval; visual quality cannot authorize
it. Read-only critique identifies friction and smallest proposals without edits.
Fresh-context review applies when required by the existing gate or user request,
not merely because the subject is UI. Existing security/privacy triggers are unchanged.
