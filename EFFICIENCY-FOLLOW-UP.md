# Longer-term efficiency follow-up

This work has no assigned release number. It does not block the bounded 0.5.1
point release or the planned UI/UX/brand capability work.

Use the [retained attribution](evals/results/0.5.1-efficiency/README.md) to rank
excess cost in release security, release privacy, authorization/export, correction
review, approved design/planning and evidence/code artifact generation. Include
real Harness usage alongside synthetic benchmarks. File size and observed reads
are proxies; report actual context/token/time costs separately.

Test one measured hypothesis at a time: reduce repeated serialization of
contracts/evidence, duplicate artifacts or unnecessary reports; improve reviewer
evidence reuse; or trim expensive owner/reference context. Retain failed attempts
and compare equivalent model/effort, source, tasks and available agents. Attribute
implementation/topology differences instead of crediting every saving to prose.

Preserve scope approval, fresh independent review, complete blockers and release
coverage, truthful unavailable evidence, and critical-progress proof. Reject a
critical regression; do not change the rubric or weaken control capability to
improve a number. Use focused evidence before considering a broader comparison.
Prefer deletion and reuse over new machinery, and stop when added complexity is
not justified by a demonstrated benefit.
